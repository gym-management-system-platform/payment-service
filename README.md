# payment-service

Сервис **шага оплаты** в саге: обработка команды из Kafka, создание и обновление записи платежа, имитация ответа платёжного шлюза (вероятность успеха настраивается), публикация результата в **transactional outbox** для `order-service`. Публичного REST API под сценарий саги нет: граница — сообщения Kafka.

## Роль в системе

По событию «заказ перешёл к оплате» сервис создаёт платёж в статусе ожидания (идемпотентно по `saga_id`: повторное сообщение не создаёт второй платёж), затем в той же транзакционной границе выполняет «обработку» и ставит в outbox либо успех, либо ошибку. При компенсации саги предусмотрена ветка возврата по `saga_id` для уже успешного платежа (смена статуса на возврат в рамках бизнес-правил сервиса).

## Таблицы (Liquibase)

### `payments`

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | UUID | Первичный ключ платежа. |
| `saga_id` | VARCHAR(100) | Корреляция с сагой; уникальность сценария «один платёж на сагу» обеспечивается логикой сервиса. |
| `order_id` | VARCHAR(100) | Ссылка на заказ (строка, как в событии). |
| `amount` | DECIMAL(19,2) | Сумма. |
| `currency` | VARCHAR(10), default RUB | Валюта. |
| `status` | VARCHAR(50) | Жизненный цикл: ожидание, успех, ошибка, возврат и т.д. |
| `payment_method` | VARCHAR(50) | Способ оплаты (в учебном коде может быть зафиксирован константой). |
| `transaction_id` | VARCHAR(100) | Идентификатор «транзакции шлюза» при успехе. |
| `error_message` | TEXT | Текст при отказе. |
| `created_at`, `updated_at` | TIMESTAMPTZ | Аудит. |

### `outbox_event`

Исходящие в Kafka события об успехе или неуспехе оплаты (и при необходимости других исходов).

| Поле | Тип | Назначение |
|------|-----|------------|
| `id` | UUID | Ключ записи. |
| `aggregate_type`, `aggregate_id` | VARCHAR | Агрегат (платёж / идентификаторы). |
| `event_type` | VARCHAR | Тип исходящего события. |
| `payload` | TEXT | JSON-текст для продюсера. |
| `saga_id` | VARCHAR(100) | Корреляция. |
| `processed` | BOOLEAN, default false | Отправлено ли в Kafka. |
| `retry_count`, `last_error` | INT, VARCHAR | Повторы публикации. |
| `created_at`, `processed_at` | TIMESTAMPTZ | Временные метки. |

## Сценарии

1. **Первая команда на оплату:** insert в `payments`, имитация шлюза, обновление статуса, insert в `outbox_event` с результатом — в одной реактивной транзакции, затем фоновая отправка в Kafka.
2. **Повторное сообщение с тем же `saga_id`:** обработка не создаёт дубликат платежа (короткое замыкание в сервисе).
3. **Компенсация после успешной оплате:** поиск платежа по `saga_id`, проверка статуса, перевод в возврат при допустимости.

## Технологии

Spring Boot 3, WebFlux, R2DBC PostgreSQL, Liquibase, Kafka, `kafka-starter`, Springdoc (если включены контроллеры для обзора API), MapStruct.
